## Career objective and stage mapping
ERP Business Process Automation Developer / ERP Application Developer. Fully remote preferred, prioritize roles accepting Canadian applicants. Apply early; readiness is evidence-based, not a guarantee or automatic eligibility. SAP is initial specialization; skills transfer across ERP platforms. No employer test server dependency.

Certification optional for early roles; verify current CAP and Integration Suite exam availability later. Verify course URLs before enrollment. No fixed completion dates; use demonstrated skills.
## Application behavior
Roadmap shows each stage with linked courses, concept mastery, assessments, projects, portfolio evidence and job targets. Current phase shows one focused next action and unmet exit criteria. Course completion and mastery are independent. Course completion prompts practice/assessment and project work; job applications remain available throughout, including stage 0. Show why a role is a fit and gaps, never lock applications behind a certificate. Proposed job tracker: title, company, URL, remote/Canada eligibility, salary if posted, requirements, fit notes, status, dates and follow-up; no fabricated listings. Allow manual entry and linking existing job-watch results, not automatic applications.
Learning library tracks course URL, status, progress, notes, certificate, phase and related skills. Skill Library registers new concepts and generates/imports practice packs as specified in Practice Lab document. Practice Lab reuses playground engine; Assessments track independent evidence. Weekly plan links sessions to course, practice queue or project; editable duration and completion, review and next actions. Default schedule from weekly schedule document; allow adjustment without rewriting historical sessions. Projects track milestones, acceptance criteria, tests, repo, screenshots, architecture, demo video, limitations and measured vs estimated impact. Portfolio view aggregates publishable evidence, not private employer data. Career checkpoints show readiness evidence and gaps and suggested job titles.
## Data and migration
Use stable IDs and explicit relationships among stages, courses, concepts, exercises, attempts, sessions, projects, evidence, checkpoints and applications. Separate content defaults from user progress. Seed missing items idempotently; never reset saved progress, notes or user-created items. Preserve existing features and records; show last-reported SQL progress as a seed only if no newer user value exists. Use authenticated persistence, export/import and revision/conflict handling. Follow Practice Lab isolation and security requirements. Verify actual Vercel/Neon/auth state before selecting migration; no secrets or employer data.
## Portfolio and readiness gates
For each stage define required skills from course guides, independent practice assessment, working project and evidence checklist. Each substantial project includes business problem, intended user, solution, architecture, stack, source, setup, tests, screenshots, 5–10 minute narrated walkthrough, results and limitations. Use synthetic data, supported APIs, validation, duplicate prevention, logging, audit trails and human approval for high-impact actions. Mark simulated integrations and estimates. Readiness suggestions must explain evidence and missing items; user can apply anytime.
## Acceptance
Claude's plan must map every requirement to existing or proposed UI, data model, migration and tests. Demonstrate end-to-end: register WITH/LEFT JOIN/CROSS JOIN/UNION, import validated exercises, practise and record attempts, update skill/review queue, complete assessment, link SQL project and portfolio evidence, see relevant job targets and track an application. Reload and verify persistence; preserve older records. Verify mobile, accessibility, worker isolation, auth, export/import and regression tests. Follow phased gates in Practice Lab spec; do not implement or deploy before approval. Proposed job tracker and relationship model are design recommendations, not existing features.
